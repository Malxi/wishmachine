# 去 AI 味工作流（风格 pass）

目标不是“写得更华丽”，而是把**默认选择**改成**这一个叙述者、这一个场景的选择**。
本工作流配合 `check --profile style` 使用；CLI 只给统计和命中位置，改写由你完成。

## 0. 先建 style 目录里的两个文件（每本书一次）

- `story/style/voice.json`：声音卡（`book read style` / `book write style`）。
- `story/style/writing-style.json`：写作风格 + **逐字人类参考样本**
  （`book read writing-style` / `book write writing-style`）。`writing_style` 不再放 setup。

参考样本不允许 AI 自己写。内置样本见 `data/style/human-samples.json`
（鲁迅《孔乙己》《故乡》《药》、郁达夫《春风沉醉的晚上》、老舍《老张的哲学》、
废名《长日》、朱自清《背影》，以及用户授权样本；公版状态与 jurisdiction 说明见
`data/style/README.md`）。写作时只取与本书语感相近的 1–3 段，写进 `references[]`，
并保留 `sample_id`、`source`、`author`、`work`、`url`，`text` 必须与目录中的
`text` 逐字一致。**不要自己概括、改写或补写样本**。

`writing-style.json` 最小形状：

```json
{
  "version": 1,
  "name": "贴着周辙的近距离第三人称",
  "description": "只写周辙此刻能看见、摸到的东西；情绪滞后，经常不写。句子长短不匀，夹半句口语。",
  "principles": ["只写人物能感知的具体物", "对话短、答非所问", "段落停在动作或物件上"],
  "avoid": ["段尾升华", "不是…而是…", "每章报数打卡"],
  "references": [
    { "source": "public-domain", "sample_id": "zh-luxun-kongyiji-01",
      "author": "鲁迅", "work": "孔乙己",
      "url": "https://zh.wikisource.org/wiki/孔乙己",
      "text": "……把 data/style/human-samples.json 中该 sample_id 的 text 原样粘贴……" }
  ]
}
```

`book write writing-style` 会拒绝：没有人类来源的 `references`、`source: "ai"`、
公版样本缺少 `sample_id` 或 text 与目录不一致、human/licensed 样本缺少
`license` 或 `user_confirmed: true`，以及把“每章/每级报数、换壳、押、仪式”
写进 principles 的节拍表。

voice card（`story/style/voice.json`）最小形状；正样本同样必须是内置 `sample_id`
或用户确认的 human/licensed 文本。内置示例在 `data/style/voice-card.example.json`
（公版样本，可直接复制后改）：

```json
{
  "version": 1,
  "narrative": { "pov": "third_person_limited", "tense": "past", "distance": "close" },
  "voice": {
    "description": "冷峻、具体、少形容词；情绪从账目和动作里漏出来",
    "principles": ["用职业细节代替抽象判断", "每段至少一个可触摸的物"],
    "avoid": ["会躁式单字谓语", "段尾升华", "不是…而是…", "三连排比"]
  },
  "samples": [
    { "label": "公版样本", "source": "public-domain", "sample_id": "zh-luxun-kongyiji-01",
      "author": "鲁迅", "work": "孔乙己",
      "url": "https://zh.wikisource.org/wiki/孔乙己",
      "text": "……把目录中该 sample_id 的 text 原样粘贴……" }
  ],
  "negative_samples": [{ "label": "反面", "source": "ai", "text": "……一段你觉得 AI 味的文字……" }]
}
```

写入：`book write style --dir <project> --apply < voice.json`（默认 dry-run）。
`style` 与 `writing-style` 都只支持 `--mode replace`，不接受 `--target`；写正文前用
`book read context` 确认 style / writing_style summary。

## 1. 设定 loop（写正文前，最多 2 轮）

设定不过关，正文怎么写都救不回来。按“四件套”过一遍：

1. **一地点**：故事发生在哪个具体地方？谁在这里工作、记账、交税？
2. **一职业**：主角每天重复的具体劳动是什么？冲突从劳动里长出来。
3. **一矛盾**：这个地方的人相信什么，现实又逼他们做什么？
4. **一代价**：力量/规则要付什么代价？代价必须能被记账、被看见。

然后跑：

```bash
wishmachine check --dir <project> --profile style --target setup
```

关注 `style.setup.genre_salad`（题材堆叠）、`style.setup.abstract_terms`（抽象词密度）、
`style.setup.theme_aphorism`（格言式主题）、`style.setup.rules_concrete`（规则不可操作），
以及 `style.setup.name_*`（姓氏集中、描述式名字、单字名、来源缺失、重名）。
取名先做 namecard pass：先定最终题材，再 `ideas draw --type namecard --genre <实际题材>
--count 20`，把选中的 `namecard_id/naming_style/naming_logic/name_source` 写进 setup；
`name_source` 只能是 `draw`（带 `namecard_id`）或 `human`（用户提供），AI 不得自己取名。
详见 `references/name-guide.md`。
改法：

- theme 不要写“守住边界的不是墙，是……”这种格言，改成一条人物每天要执行的规矩。
- 规则必须写清“能做什么、不能做什么、违反后付什么代价”，而不是“四样作物就是四座塔”。
- 题材选一个主类型，其余作为**代价机制**存在，不要并列成卖点。

## 2. 章节 loop（每章，最多 2 轮）

1. 按 outline + voice card 写初稿。
2. 体检：

   ```bash
   wishmachine check --dir <project> --profile style --target chapter --id P1-V1-C1
   ```

3. 看 `findings` 里的 `metrics.value`、`threshold` 和 `evidence`，**只改命中句/段**，
   不要整章重写。优先处理 medium：单字谓语、否定式谓语、句首复用、段尾升华、比喻密度。
4. 做中文句法 pass（先查最显眼的一两种，不要全项配额）：
   - `style.chapter.translationese`：删“对于…来说/在…背景下/随着…发展/与此同时/使得…得以”，
     先写谁做了什么，再把条件、时间放到动作附近。
   - `style.chapter.nominalization`：把“进行讨论/作出判断/实现提升”还原成具体动作；
     必要术语保留，不要机械拆词。
   - `style.chapter.jargon`：删不承担信息的“赋能/抓手/闭环/颗粒度/底层逻辑”，
     换成具体对象、动作、代价。
   - `style.chapter.emotion_body`：情绪可以直说，但要写清怕谁/怕什么；
     身体反应（瞳孔骤缩/呼吸一滞/心脏漏跳）必须改变后续动作。
   - `style.chapter.soft_adverbs`：微微/缓缓/淡淡/轻轻 不要当标点用；删一半，换具体动作。
   - `style.chapter.dialogue_tags`：少用“淡淡道/低声道/冷冷道/薄唇轻启”，
     用动作、停顿、答非所问代替。
   - `style.chapter.subtitle_paragraphs` / `subtitle_run`：普通动作/判断并回同一段；
     单句成段只留给真正的重音（情绪爆开、认知推翻、重大选择、章尾钩子）。
   - `style.chapter.lecture_markers`：删“本质上/真正重要的是/这说明”等抬升壳，
     直接写事实、后果或人物判断。
   - `style.chapter.qa_rounds` / `one_line_dialogue`：先问“这句对白有必要说吗”；
     重复确认、已知信息、无后果寒暄转成动作或叙述，别让对白垄断推进。
   - `style.chapter.punctuation_tic`：只有破折号/冒号/分号密度极高时才处理；
     先重写句法关系，再选标点。
5. 复检；指标回到健康带或你明确接受即可，**不要追求 0**。
6. 朗读一遍，人工抽检“像不像人写的”。
7. 把本章新发现的“用滥词/句式”写回 voice card 的 `voice.avoid`（`book write style`）。

**编辑授权**：style pass 默认只改命中句/段，不整章重写；如果用户只要“审稿/标问题”，
只引用问题片段和修改方向，不交改写稿。对白里的翻译腔/黑话/标签可能是人物声口，
先判断“这个人物会不会这样说话”，不要一律删。

每场戏先过“目标/阻碍/转折/结果”四件事；连续两段没有新信息就合并或删。
同一母题（数、纸边、账、六、第七垄）全书超过 3 次就要升级代价或认知，
纯仪式性重复直接删；`style.motifs` 和 `style.book.repeated_motif` 会量化这件事，
详见 `references/scene-guide.md`。

### 关键指标与目标

| 指标 | 目标 |
|---|---|
| 单字谓语收尾 | ≤2.0/千字（第七垄基线 3.2） |
| 否定式单字谓语占比 | ≤50%（第七垄 85%） |
| 句首复用率 | ≤30%（第七垄 54%） |
| 主角名开头率 | ≤8%（第七垄 12%） |
| 段尾升华 | ≤0.3/千字 |
| 模板连接句 | ≤0.8/千字 |
| 比喻密度 | ≤2.5/千字 |
| 对话占比 | 8%–35% |
| 翻译腔连接 | ≤1/千字 |
| 名词化/弱动词 | ≤1.5/千字 |
| 互联网黑话 | ≤1/千字 |
| 身体表演式情绪 | ≤1.5/千字 |
| 弱化副词 | ≤8/千字 |
| 对白标签 | ≤1.5/千字 |
| 非对白单句段占比 | ≤25% |
| 连续非对白单句段 | ≤2 |
| 抽象抬升句 | ≤0.8/千字 |
| 连续问答轮数 | ≤2 |

指标是**方向**不是 KPI；如果为了达标把句子改得机械，就是另一种 AI 味。

## 3. 书级 loop（每 3 章）

```bash
wishmachine audit --dir <project> --profile style --view summary
```

看全书 `metrics`、每章 `metrics` 和每章 `shape`：某个指标中位数超线、或后几章比前几章
恶化 20%，就是风格漂移。把漂移写回 voice card，下一章开头重新注入。

同时看结构层：

- `style.book.shape_convergence`：至少 3 章共享同一开头/收尾/结构签名；
  换一种进入方式或落点，但不要为了打散结构随机换开头。
- `style.book.theme_explicitness`：多章以主题总结/抽象抬升收尾；
  把主题留给情节和代价，至少让一章停在具体动作或未解释的细节上。
- `style.book.repeated_motif`：跨章重复的描写/动作短语；每次重复都要升级代价或认知。

## 4. 改写手法（按优先级）

1. **具体性置换**：抽象判断换成只有这个人物/职业/地方会注意到的细节。
2. **中文句法还原**：先找“谁做了什么”；删“对于…来说/在…背景下/随着…发展”等连接壳；
   把“进行讨论/作出判断/实现提升”还原成动作；拆开过长的定语链，少用连续“它/该/其”。
3. **句法去模板**：删“不是…而是/不仅…还/首先其次最后”；段尾停在动作或对话上；
   句子长短故意不匀。
4. **重复纪律**：重复只在信息升级时用（第二次数出第七垄、代价变了），否则删。
5. **对话口语化**：半句、抢话、答非所问、行话；叙述里少用“她说”，多用动作和停顿；
   先删重复确认/已知信息，再改说法。
6. **段落纪律**：一个自然段完成一个连续过程（动作→观察→判断→反馈）；普通动作/判断
   并回同一段，单句成段只留给真正的重音。
7. **场景裁剪**：晚进早出；砍 30% 世界观解释，让设定从动作和账目里漏出来。

## 5. 反例（第七垄实测）

- ❌ 马拉进去会躁。沈穗没争。
  ✅ 车夫说，马进了那块地就烦躁，怎么打都不肯往前走。沈穗没说什么，把箱子从车上提下来。
- ❌ 她数了一遍。六垄。又数了一遍，还是六垄。
  ✅ 她扫了一眼，有六条田垄。

## 5b. 四类反复出现的句子病（悬疑题材实测，同 seed 两轮复现）

这四类在两次独立生成里都出现，也都在 `check --profile style` 的命中项里。规则是"删"或"限量"，
不要靠"写得更文学"来解决。

### ① 段尾判断句（`paragraph_uplift`）

现象：几乎每个自然段的最后一句都落在抽象判断或总结上，像作者在段落末尾给读者划重点。

- ❌ ……锁舌缩在门里，弹簧上挂着新油。这扇门从外面锁不上，里面也没人动过插销。**封条是贴给人看的。**
- ❌ ……红框超过三处，回执盖作废章。**机器只认字。**

这类句子本身不坏，坏在**密度**——每段都来一句就变成节奏器。规则：全章这类"段尾判断"
**不超过 2 处**，其余段落收在一个动作、一句对话或一个物件上。

- ✅ ……弹簧上挂着新油，油还没干。他没碰，蹲下去把手电照进插销孔。

### ② 模板连接句（`template_connectors`）

- ❌ 不是他慢，而是对方太快。 / 不仅没锁，还挂着新油。 / 首先查门，其次查钥匙。
- 规则：删掉连接壳，写两个并列事实，让读者自己连起来。
- ✅ 他回身看门。锁舌缩在里面，油是新的。

### ③ 忽然 / 突然（`time_emphasis`）

这个词本身不是问题。判断标准是它**替代了因果**，还是**给动作开闸**。

- ❌ 尸袋里那只手**忽然**从袋口滑出来，指尖碰到推车边缘。
  —— 跳过"袋子为什么会松"，用副词顶替动作链。
- ✅ 他抽走回执，袋口一松，那只手滑出来撞在推车边上。
- ✅ 经典用法可对照：鲁迅《药》"……什么都睡着。华老栓**忽然**坐起身。擦着火柴，点上遍身油腻的灯盏……"
  —— 从静到动的那一跳需要一个标记，而它后面立刻接具体动作。

规则：可以用，但**开闸之后必须紧跟具体动作或原因**；不得用它替代因果。同一章不出现第二处。

### ④ 计数罗列（`enumeration`）

现象：一段里堆三组以上"几X / 第几 / 多少"的清点式写法。

- ❌ 编号 M-011，原先存过 M-010。三号间、七号柜、B7。名单七页，拿到六页，第十一行是铅笔字，前十个划掉九个。
- ✅ 编号是 M-011——上一具是 M-010，早烧了。名单在第七页断了，前面是打印的，往后是铅笔。

规则：同一段"清点式"写法全章不超过 2 处；数字只保留**读者必须记住的那几个**，其余换成相对说法或人物的话。

**序列脚手架**：`先…再…最后` / `首先…其次…最后` 是模型最顺手的三人步式。它只该用在人物真的在做
三步操作时（先拆封条、再看锁舌、最后推门），不能用它代替回忆、列举或转述。

- ❌ `闻既白闭上眼，先报天气，再报路灯，最后说穿雨衣的人走进北槐路地下室。`
  —— 证人回忆被写成了流程清单，读者看不到他停顿在哪、犹豫在哪、哪一段记不清。
- ✅ `闻既白闭上眼。雨下到九点二十就没停，路灯亮着，一个穿雨衣的人从灯下走过去，进了北槐路地下室。`

全章序列脚手架不超过 1 处；出现第二处就改成自然语序，允许人物跳过、记错、说不清。

### ⑤ 别把压缩谓语清零（`predicate_variety`）

§5b 前四条的修法容易被执行成"一律删短"，实测就出现过：压缩/单字谓语被删到 0，
`predicate_variety` 报 0（healthy ≥ 0.85）——从一个极端掉到另一个极端。

- 规则：全章**保留 2–4 处**单字谓语（"锁舌缩在门里""油没干""他没争"），放在动作收束处；
  其余句子该展开就展开。目标是"不集中"，不是"清零"。
- 同理：短句比例（`short_clauses`）落在 0.2 附近即可，不要为了"简洁"通篇电报句。

### 别拿指标去审样本（元规则）

公版样本是**校准基准**，不是待检对象。`check --profile style` 的阈值是按"LLM 密度"定的，
它命中的词在经典段落里往往密度更高——实测同一批实验：鲁迅《药》片段"忽然"2.68 次/千字，
而生成的正文是 0.00–0.65 次/千字。所以：

- 指标和样本冲突时，**先怀疑阈值**；不许为了指标改样本，更不许绕开"带禁字的"经典段落。
- 样本唯一的硬约束是**禁止整句搬运**——学句式呼吸和段落收束方式，不是搬句子、不是搬一份词语清单。
- 同理适用于 §5b 四类：命中只说明密度，不说明那句话坏。动手前先问一句"它替代了什么吗"。

### ⑥ 机制与设定不许用比喻和生造词交付

§5b 前五条管句子病，这一条管**信息交付**。实测：一章 style 95 分、四类句子病全零，仍然出现下面六种
“看不懂”的句子——指标测不出来，只有人读才发现。

自检方法：把这句话单独拿给不知道设定的人看，他能不能说出“谁做了什么、看见什么、后果是什么”？
说不出来就是谜语。

- ❌ 用比喻概括机制：`机器读走他最近二十四小时，把一天压成一条灰线。`
  ✅ 屏幕上一条线在走，走到第四十一分钟变红，旁边的数字停住。
- ❌ 生造压缩词：`本次鉴定扣减一案额度。`
  ✅ 这一读，本月能调的卷宗少一个。
- ❌ 缺介词的状语压缩：`七号房那晚，你看见谁出来？`
  ✅ 七号房那天晚上，你看见谁出来？
- ❌ 把概括塞进人物嘴里：`案子卡在"谁进得去、谁出得来"。`
  ✅ 门从外面贴的封条，窗子没开，人却死在里头。谁进去的、怎么进去的，到现在都对不上。
- ❌ 因果倒装 + 指代模糊：`名单一旦进卷，活人也会被点名。……除了外面的人，名单上已经全被划掉。`
  ✅ 名单进了卷宗，被告也能翻。上面只剩一个名字没划——你念出来，等于替他点了一个。
- ❌ 同一行重复同一个实词：`拿笔在纸表上记下一笔……笔尖顿了顿，又把数字描粗。`
  ✅ 低头在纸表上写了个数，写完又描了一遍，把笔画压得很重。

规则：屏幕上是什么、手在做什么、纸上写着什么字、数字变了多少、谁因此付出什么——写这些。
行业词（卷宗、额度、扣减）可以用，但第一次出现必须让不熟的人靠上下文猜得出；猜不出就换成后果。
人物台词必须是具体主张，不是谜面。

#### 复述测试（金句专用）

一句"听起来很好"的话，必须能**改说成一个事实**：谁做了什么、谁会怎样。复述不出来的，就是搭配错或谜语，
不管它多像金句。

- ❌ `死的是名字。名字不死，活人就得死。`
  —— 名字不能"死"（"死/活"是生命的动词，只能配人、动物、植物）。读者要先在心里做一次"他是在比喻"
  的换算，那一下就是卡顿；而且"名字活着→活人就得死"的因果也复述不出一句事实。
- ✅ `死的是登记页上那一栏。人还活着，名字注销了。`

中文里"名字"能配的动词很窄：**登记、注销、更改、抹掉、顶替、划掉、写错、对上**；
**不能**配 死、活、流血、呼吸。行业动作换成正确的动词，句子自己就清楚了。

**注意不要把这条写成词表禁令**：`证据链断了`、`编号从中间断开`、`名单上还有活人` 都是正确搭配。
实测 12 章里"抽象名词+生命动词"的粗筛命中 14 处，其中 13 处是误伤 —— 所以这条靠**人读**，
或者用 `tools/check_collocation.py` 把候选句报出来给人挑，不要自动判违规。

### ⑦ 指代与场景连贯

§5b⑥ 管“能不能读懂”，这一条管“读的时候会不会卡住”。实测第 7 轮：六类谜语句全清零，但出现了下面三种卡顿。

- **代词必须段内有唯一所指**。台词里的“他/她/那边”，读者要立刻知道是谁；不能靠七八行之后的人物出场解围。
  ❌ `“你问我，不如问他。”程无咎侧过身。`（“他”要到八行后才进门）
  ✅ `“你问我，不如问他——授权书在他手上。”`
- **二次画面要交代形态和来源**（记忆投影/监控/纸带/别人转述）。画面里出现不合常理的东西（死了的人动了），
  至少给一个可核验的物证线索（时间戳、断口、灰边），不要只用“像在说话”这类灵异化比喻糊过去。
  ❌ `第二具尸体的脸从门后露出来，嘴巴一张一合，像在说话。`
  ✅ `第二具尸体的脸从门后露出来，嘴在动。纸带上的时间戳跳到 01:07——比他进门早了两个小时。`
- **“某人把某物怎么样”句式全章不超过 2 次**，其余改成物作主语或省略主语。
  ❌ `罗观衡把袋口解开……罗观衡把回执推过去……罗观衡把纸带翻过来……罗观衡把登记板往前翻。`
  ✅ `袋口的塑料绳松开又扣回去。回执推到鉴定机前。纸带翻过来，背面有一列涂黑的字。`

## 6. 腔调抽卡（stylepack）与改写 pass

`ideas draw --type stylepack --genre <题材> --seed N` 抽一张叙述腔调卡：voice / register / rhythm /
imagery / advance + 公版 sample_ids，外加两样**可校验**的东西。验收脚本：
`python3 tools/check_stylepack.py <章节.md> <stylepack.json>`。

**一稿就该达标的（实测可行）：**

- `rhythm_target.paragraph_sentences`、`sentence_mean_chars`：段均句数与句长均值的区间。
  实测能把段均句数从 2.35 抬到 3.96、句长均值从 13 抬到 16，落在给定区间内。
- `imagery_lexicon.allow` / `.ban`：意象白名单与黑名单。`ban` 必须出现 **0 次**——
  实测把「门/走廊/灯」从每章十几次压到零是可行的，这是治「每本书都是同一间停尸房」最有效的一条。

**不要写成一稿验收线（实测做不到，硬追会把文章写成台账）：**

句长 cv、短句占比、段末落点配比。十轮实测：段末动作占比目标 35%，一稿只做到 8%，
而为了凑数文字变成了流程清单（style 分反降到 74）。这三项属于改写 pass。

### 改写 pass（第二稿才做）

- 逐段只看段末一句：把它从抽象判断改成动作、对白或物件。
- 短句占比按卡面调：需要碎就把长句拆成两三个短句；每拆一次确认信息没丢。
- 判改好没有，用 `tools/check_stylepack.py` 那行“参考”前后对比，不追求归零。

## 7. 不要做的事

- 不要先写得很 AI 再整段 humanize：信息结构已经被模板化了，humanize 只能洗表面。
- 不要为了指标归零反复润色；最多 2 轮。
- 不要把 voice card 写成“文笔优美、情感细腻”这种空话；写可执行的禁令和样本。
- 不要把 `check --profile style` 当 blocking gate；它是体检，不是裁判。
